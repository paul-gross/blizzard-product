# Epics

The registry of blizzard's live epics: the capability areas the product is built from, in priority order — the order of
the rows is the order of the plans behind them. An epic is a capability area, not a version, and it may land in slices.
Each epic serves one or more destinations in [milestones.md](./milestones.md); this is a reference list of what is being
built and why, not a status board — how refined each epic is and where its slices actually stand live in the epic plan
each row links, and a slice that has fully landed resolves in [delivered.md](./delivered.md) once the milestone it
served is reached.

| `epic:advanced-delivery`   | Finished work that lands the way its project needs it to land. | `epic:advanced-deployment` | Landing is not the finish line for an operator whose work has to run somewhere. The road from merged to running is whatever each deployment happens to be — an image a host polls for, a runner someone rebuilds by hand — and an agent improvising those steps is the least trustworthy hand to put on production. Here each repository declares, deterministically, how it deploys: the steps, the order in which repositories depend on one another, the smoke checks that prove a deploy healthy, and the procedure that undoes it. Once a chunk lands, a delivery train works out which repositories changed, deploys them in dependency order, and validates each before the next one moves. Where judgement is genuinely needed, the train runs a graph on a chosen model: one agent reads the evidence and decides whether the deploy is healthy, broken, or due for rollback; the rollback runs as its declared procedure; and a second agent confirms it took. An agent deploying by hand remains, as the fallback rather than the method. | Follows `epic:projects`, whose project links decide which repositories a chunk's work may reach, and builds on `epic:advanced-delivery` knowing which repositories a chunk landed and in what order. | `epic:chokepoint`          | Room for the change a project makes a few times a year: a rewrite from Python into Rust, a move from one framework to another, a generation of dependency upgrades, a tech-debt sweep across the whole codebase. Work can also arrive already carrying its urgency: a routine names the urgency of what it mints, and a work item's own stated priority maps onto one.                                                                                                                                                                                                                | Rank still orders the queue and the work within each urgency.
