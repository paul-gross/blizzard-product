# Epics

The registry of blizzard's live epics: the capability areas the product is built from, in priority order — the order of
the rows is the order of the plans behind them. An epic is a capability area, not a version, and it may land in slices.
Each epic serves one or more destinations in [milestones.md](./milestones.md); this is a reference list of what is being
built and why, not a status board — where an epic's slices actually stand is tracked in the milestone epic charts and in
GitHub, and a slice that has fully landed resolves in the epic chart that marks it `delivered`, then in
[delivered.md](./delivered.md) once the milestone it served is reached.

Guidance stays small enough to be read and load-bearing enough to be followed; drift is named while it is one commit old rather than discovered as spaghetti. | Operational necessity, twice over: the corpus only accretes — every retrospective proposes rules, and no standing process removes anything — and the code accretes faster than human review can hold an architecture line, where a constraint binds only if something checks it. Plan: [mutation-testing](./plans/mutation-testing.md).                                                                                                                                                                                                                                                                   |
