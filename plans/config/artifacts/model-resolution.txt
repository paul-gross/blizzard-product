Worked sample: `blizzard runner models --chunk …` on one illustrative runner.

The runner has Claude Code and OpenCode enabled, with Claude Code as its default. Its blizzard-runner.toml carries:

    [models.aliases]
    "blizzard:frontier" = "opus"                      # cheaper than the built-in fable

    [opencode.models.aliases]
    "blizzard:frontier" = "anthropic/claude-opus-5"   # edited this morning; was claude-opus-4
    "blizzard:advanced" = "openai/gpt-6"

    [opencode.effort.aliases]
    "max" = "high"

The chunk runs basic-harness-workflow as the hub ships it: code on blizzard:frontier; gate, iteration, and prepush on
blizzard:advanced; no effort or harnesses declared. Someone set the chunk's defaults to effort `xhigh` and harnesses
`opencode, claude_code`. The runner has already minted the code and iteration pools for this chunk.

Reading it the morning after: every session is running with no effort at all, because the chunk's `xhigh` is not a
value either harness knows. Every session lands on OpenCode rather than the runner's default, because the chunk put
OpenCode first. And the code pool is still on the model it was minted with, because it has not rotated since the alias
changed. Each of those three answers came from a different layer, and each is visible on one screen.
