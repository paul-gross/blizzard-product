Sheet 2 — runs, findings, and the triage of them

The run list is the trendline, itemized

Every run has a row, including the clean one and the escalated one. Their counts read +added / ✓observed / ∅gone — a delta, never a restated state.

Two lists, one panel

“This run” is what the run touched; “live bucket” is everything still open on the routine. The same triage works in both, because triage is a property of the finding, not of the run that happened to raise it.

Gone is a flag, not an exit

Findings a run reported gone stay in the live set, tinted, with the run's own note attached. A person accepts the report or does not. That is the rule the whole sheet is built around: a finding leaves the live set on human judgment and never on a pass's word.

Proposed — dispositions, not one “withdraw”

machinery.md names three exits: work landed, a person withdrew it, a person accepted a gone report. This sheet splits the withdrawal into won't fix, not a finding, and superseded, because collapsing them makes outflow a number you cannot read.

“We fixed it” and “it was never real” are opposite facts. The second is feedback on the strategy — the routine's false-positive rate, shown beside the tabs — and a class with a high one is a prompt to sharpen or to stop paying a model to judge it.

Accepting a proposal moves nothing here

A finding whose proposal was accepted stays open, with the work item shown beside it as a link. A decision about a proposal is never an observation about the ground — the finding leaves the live set when a run reports it gone or a person withdraws it, and not a moment earlier.

Only resolved counts as outflow

Won't-fix and not-a-finding leave the live set without tending anything, so they are excluded from the outflow trend and the triage dialog says so before you commit. Otherwise a bad week of triage reads as a good week of gardening.

Bulk, because a finding is one instance

Seventeen instances in a package are seventeen rows. Triage without multi-select would make the honest granularity unusable — which is how a store quietly drifts back toward themes.

The note is the point

Every state change carries free text, and the row keeps showing it. A finding struck as not-a-finding with no reason teaches the routine nothing, and the next run raises its twin.

Nothing is deleted, ever

Reopen restores open with the id, the first-seen instant, and every run that touched it intact. The hub mints ids; an agent never invents one; and a round trip through triage cannot cost a finding its history.

The chunk is a link, not a surface

A run is a chunk like any other. The header offers one jump to the board and the tab rebuilds none of it — the orchestration layer has never heard of any of this, and the UI keeps it that way.

Open — what a pass sees of triage

A withdrawn finding leaves the live set, so blizzard hub finding list stops returning it and the next run may raise its twin. Whether withdrawn findings are exposed to a pass as “already-judged, do not re-raise” is unsettled, and it is the difference between triage that holds and triage you redo monthly.
