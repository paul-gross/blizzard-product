# Surfaces

Every surface `docs/versioning.md` names is a committed contract document, generated from the code, held to it by a
drift check in the gate, and diffed by one classifier against each supported release's copy
([baseline.md](./baseline.md) §A release's surface). A classifier is pure — two parsed documents in, a list of
`Violation(surface, where, reason, deprecated)` out — and unit-tested on hand-built fixture documents, never the
committed ones, as `tests/test_wire_compat.py` tests `classify_spec_diff` today.

Each surface has one way to mark something **deprecated**, and a classifier sets `deprecated` on a finding when the
baseline carried that mark on the thing the finding removes or changes. Marking something deprecated is itself additive.

| Surface         | Document                                                             | Generated by                         | Deprecated mark                                                           |
| --------------- | -------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------- |
| hub↔runner wire | `openapi/hub.openapi.json`, the wire selection                       | `blizzard-export-openapi`            | `deprecated: true` on the operation, the property, or the enum's schema   |
| HTTP API        | `openapi/hub.openapi.json`, `openapi/runner.openapi.json`, all paths | `blizzard-export-openapi`            | the same                                                                  |
| Configuration   | `contracts/config/hub.json`, `contracts/config/host.json`            | `blizzard-export-contracts`, new     | `deprecated` and `replaced_by` on the key or path                         |
| Trace contract  | `contracts/traces/dictionary.json`                                   | authored; `blizzard:trace-contract`  | `deprecated: true` on the span, event, or attribute entry                 |
| Egress contract | `contracts/egress/dictionary.json`                                   | authored; `blizzard:egress-contract` | `deprecated: true` on the dataset major or column                         |
| Store schema    | `contracts/store/hub.json`, `contracts/store/runner.json`            | `blizzard-export-contracts`, new     | `info={"deprecated": "<line>"}` on the `Table` or `Column` in `schema.py` |

## Wire and HTTP API

`classify_spec_diff` (today `src/blizzard/tools/wire_compat.py:358`) keeps its rules — a removed path or method, a
request field newly required, a response field removed, a type changed, a closed enum gaining a value in a response or
losing one in a request, a union narrowed — and gains a selection argument. The wire selection is today's
`_is_surface_operation`: every `/api/fleet/...` path, `POST /api/runners`, `POST /api/hosts`, and the federation routes
a runner calls. The HTTP API selection is every path in both documents, so the wire is the subset whose consumers the
skew window governs and the API is the whole surface every other client — the CLI, an operator's scripts — reaches. A
wire finding is also an API finding; the tool reports it once, under the wire.

A wire deprecation carries a promise the classifier cannot see from the hub's document alone: the runner of the release
that deprecates an operation or field no longer calls or sends it, so a runner at the floor never depends on what the
floor deprecated. `tests/test_runner_hub_client_deprecations.py` drives every `HttpHubClient` method
(`src/blizzard/runner/hub/internal/http_hub.py`) through a recording transport and fails when one reaches an operation,
or sends or reads a field, that the tree's own `hub.openapi.json` marks deprecated. FastAPI emits the operation mark
from `deprecated=True` on the route and Pydantic the property mark from `Field(deprecated=...)`.

## Configuration

Neither daemon declares its keys today: each section reads its table through `Table`
(`src/blizzard/runner/config_table.py`) and `tomllib` on demand, so the set of keys exists only as the sum of every
read. This epic declares them. Each daemon gains a registry, `src/blizzard/hub/config_keys.py` and
`src/blizzard/runner/config_keys.py`, of `ConfigKey(path, type, required, default,
deprecated, replaced_by)`, where
`path` is the TOML path with array tables marked (`tracing.endpoint`, `runner[].harness.claude_code.model`). Every
`Table` read names a declared key; under the test suite `Table` runs strict and an undeclared read raises, so a key the
registry does not name cannot be read. The registry also lists the durable paths under each runtime root that
`docs/backup.md` documents, from the layout constants that already name them (`src/blizzard/runner/host_layout.py`, the
hub's runtime layout).

`blizzard-export-contracts` writes the two documents, sorted and stable, and the gate's contract-drift step runs it and
fails on a diff, as the OpenAPI step does. The classifier reports a removed key or path, a key whose type changed, and a
key that became required.

`[flags]` in `blizzard-hub.toml` and `blizzard-host.toml` is an open table whose keys are flag names, not configuration
keys (`epic:release-engineering/dark-launch`'s [reading contract](../../dark-launch/spec/reading.md)). The registry
declares it as one entry, `flags` of type `open table`, and the classifier diffs that entry and ignores the keys inside
it, so a flag added or retired is never a configuration finding; whether a flag may go is dark-launch's to judge.

## Trace and egress

Both dictionaries are authored and already held to the code by their own checks; this epic adds only the diff against a
release. The trace classifier reports a span name, event name, or attribute removed, and an attribute whose type
changed, and leaves the existing rule that a breaking change raises `schema_version` to `blizzard:trace-contract`. The
egress classifier reports a column removed or retyped, a nullable column made required, and a dataset major the baseline
wrote that HEAD no longer writes; a new major written beside the old is additive. A rename is reported as the removal of
the old name, which is the break `docs/versioning.md` already says it is.

## Store schema

The document is generated from each store's `schema.py` metadata (`src/blizzard/hub/store/schema.py`,
`src/blizzard/runner/store/schema.py`): every table and column, with its portable type name, nullability, whether it has
a server default, its primary key, unique constraints, check constraints by name, foreign keys, and its `deprecated`
mark, plus the store's head revision id. A component test migrates an empty store to head on SQLite and on Postgres and
compares its reflection with the document, so the document is what a migrated store is, not only what `schema.py`
claims.

The classifier holds `bzh:store-expand-contract`. A revision may expand — a table, a nullable column or one with a
server default, an index, a value. Everything else is a **contraction**: a table or column dropped or renamed, a type
changed, a column made `NOT NULL` without a server default, a unique or check constraint added to a table that already
existed, a primary key or foreign key changed. A contraction is a finding like any break, and passes only where a break
may ([gates.md](./gates.md)), and only on a table or column every supported release marks deprecated.

The reason is the downgrade. A daemon refuses a store whose revision is not its own (`bzh:manual-migrations`), so the
only way a release inside the window meets a newer store is by walking it back (`docs/rollback.md`), and a walk back
across an expansion is lossless while one across a contraction is not. The rehearsal proves the walk
([rehearsal.md](./rehearsal.md) §The store walk).

The store document's head revision is also what the rehearsal walks back to and what
`epic:release-engineering/release-lines` folds the history up to, read from the oldest supported release's tag.
