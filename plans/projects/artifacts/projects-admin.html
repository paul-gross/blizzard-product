After projects — configuration grouped by the body of work it serves

Three levels, each in its place

Tenant (header): who you are working as, part of the URL. Tenant-wide (Admin strip): members, projects, work sources, repositories, secrets, and the changes log. Project (inside a project): the sources and repositories it links, and who serves it. Gardening is per project too, under its own tab.

Work sources are shared; projects link them

A work source is a connection to a tracker — one Jira site with a hundred projects’ tickets, one GitHub repository’s issues. It is configured once, for the tenant. Each project links the sources it draws from, optionally narrowed to a Jira key or a repository, and an item joins a project when it is ingested into it.

Repositories are shared too

A repository is configured once for the tenant. A project links the repositories its work may land in, and the hub refuses to land anywhere else. grosscode-ui-kit is linked by winter and celestial: both land on its one base branch, taking turns. infra-archive is linked by nothing, so nothing lands there.

Ingest chooses the project

From inside a project, ingest is already pointed at it. Elsewhere, ingest names both the source and the project — unless the source is linked to only one project, which settles it.

A lens, not a wall

The project lens in the app strip narrows every tab to one project; All shows the whole tenant. With the lens on a project, Work sources shows only the sources that project links.

Overview answers “is this project wired?”

Work comes in (a linked source), goes out (a linked repository), and gets done (a runner serving it). A project missing one says so — celestial has no runner, so its work waits.

Secrets stay tenant-wide

Sources and repositories are the tenant’s, and so are the credentials they name; a secret lists every record that uses it.

Open — the hub source

Shown as one built-in hub source for the tenant, linked to every project, with an accepted garden proposal ingested into the project it was about. The alternative is one per project.

Open — what a link may narrow

A single Jira key or repository is shown. A query or label would be more expressive; whether narrowing filters what may be ingested, or only what is offered by default, is undecided.
