Gardening, per project

Gardening is a project's own discipline

Every noun on this tab — scopes, routines, runs, findings, proposals — belongs to exactly one project. With the lens on a project, the tab is that project's garden. With the lens on All, there is no tenant-wide garden to show, so the tab is a doorway: each project's standing at a glance, and a way in.

Where am I

The breadcrumb is the location and mirrors the URL: Gardening › blizzard › Proposals is /t/grosscode/gardening/blizzard/proposals. Gardening goes back to the doorway; the project crumb switches project in place and keeps you on the same surface. The four surfaces below it are tabs within that one project.

The lens and the crumb agree

Choosing a project here sets the app-wide project lens, and setting the lens elsewhere opens that project here. There is one notion of “the project I am looking at”, shown in two places.

Same four surfaces as today

Scopes, routines, runs & findings, and proposals keep the shape the delivered gardening screens have. What changes is that each list holds one project's records, and the strip says which project that is.

Names only need to be unique inside a project

hub-api is a scope in both blizzard and winter, and both have a garden-weekly routine. They are different records that happen to share a name.

A routine runs a shared graph

Graphs stay a tenant-wide library, so two projects' routines can run the same graph; each run is the project's own, sweeps that project's repositories, and files its findings there.

An accepted proposal becomes the project's work

Accepting a proposal raises an item in the tenant's built-in hub source and ingests it into the project the proposal was about, so the work it becomes is queued there.
