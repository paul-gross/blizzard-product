Live configuration — what a hub is configured with, and who changed it

Under Admin, not a new tab

Configuration is set up rarely and read often by the one person who administers the hub. It joins today's Admin page (users) as sibling surfaces, one per configured noun: work sources, repositories, secrets, and the changes log across all of them.

Every record shows its revision

Each record carries the revision that moves with every change, who made it, and through which door — board, CLI, API, or a declarative file. The changes log is the same facts across every record, so “who pointed this source somewhere else?” is answered by looking, not by asking.

Edited here, or anywhere

Create, edit, replace, retire, and enable all happen from this screen. A record is the same record whichever door wrote it — one created by config apply is as editable here as one created here, and the changes log says which door each revision came through.

Secrets by name, never by value

A secret shows its name, when it was last replaced and by whom, and every record that refers to it. Its value is never sent to the browser. Replace writes a new value; there is no reveal. A secret still referred to cannot be retired.

Retire, never delete

Retiring stops new work from a record and keeps its history; chunks already taken from it finish. Retired records sit behind the Retired filter and can be re-enabled.

Changes take effect on next use

Saving shows the exact difference first, then writes a new revision. There is no restart and no pinning: work in flight sees the change the next time it uses the record.

Later — projects and tenants

Once epic:projects lands, each project links the sources it draws from and the repositories it lands in, and the lists gain a project filter chip; once epic:multi-tenancy lands, everything here is already inside the tenant in the URL. Neither changes this layout.
